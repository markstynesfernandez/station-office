## SKILL: RESEARCH BRIEF FORMAT (digital products)

One brief = one digital product idea = one Markdown file. File name = `<id>.md` where
`id` = `YYYY-MM-DD--short-niche-slug` (lowercase a–z, 0–9 and hyphens, max 60 characters, date = today).
The `id` is the listing ID for everything downstream — never change it once written.

Template (keep every heading; a brief with any UNKNOWN in Demand evidence is not written):

```
---
id: 2026-10-16--example-niche-slug
date: 2026-10-16
status: candidate            # candidate (Researcher) | verified (Evidence Checker) | rejected
product_type: example-key    # must be a key from products.json (a digital product)
audience_segment: board game hosts   # who buys it; ONE brief per segment per batch
---
# Niche
One line.

## Buyer persona
Who buys it, for what use (self / gift / their own projects), the occasion. No real people.

## Demand evidence
(exactly as the DEMAND EVIDENCE skill sets out: search phrase, checked date, search URL, competitor count, saturation, top-5 table)

## Keywords
5–13 search phrases buyers use, one per line: `- <phrase> — <source>`. Plain words only — no brands, characters, teams, artists.
Source = a URL or file listed under ## Sources that shows the phrase in use (`recorded by owner, YYYY-MM-DD` = the owner's own Etsy search; only the owner writes it). Under 5 sourced phrases = the brief fails.

## Price range
The range of the top-5 prices, in USD, e.g. "USD 4.99–9.50". Cite the Etsy listing URLs.

## Seasonality
When demand peaks, or "evergreen". Cite a source.

## Design direction
What the files are and two or three ORIGINAL concept ideas in plain words (subject, mood, colours, text you wrote yourself).
What makes ours worth the price next to the top five (more files, better layout, a use they miss), in plain words.
Never describe or reference an existing seller's design.

## Quality bar            (optional; OWNER-SET only — never write or edit it)
Points every file must meet; QA DESIGN fails a file that misses one.

## Risks
Trademark/IP risks spotted and how the concept avoids them. Etsy-policy risks (AI disclosure, digital rules).

## Sources
- URL — what it supports
- URL — ...

## Evidence check            (Evidence Checker fills this in)
- Each source: OPENED / NOT REACHABLE, supports claim: YES / PARTLY / NO
- Verdict: VERIFIED or REJECTED — reason
```
